# ADR-002：API 版本化 `/api/v1`

- 状态：已接受（2026-09-02）
- 涉及：P1 代码结构与可维护性（评估并落地）

## 背景

业务接口此前零散使用 `/api/auth`、`/api/cycles`、`/api/stats` 等无统一版本前缀路径。未来模型升级（预测结果结构变化）、请求/响应模型调整时，无法在不破坏既有客户端的条件下演进。

## 决策

- 所有业务路由统一挂 `/api/v1` 前缀：
  - `auth` → `/api/v1/auth`
  - `cycles` → `/api/v1/cycles`
  - `daily_logs` → `/api/v1/daily_log` 等
- 保留 `/api/health` 为无版本前缀的探活端点（运维探活不随业务契约版本化）。
- 前端 `VITE_API_BASE_URL` 保持 `http://localhost:8000`，请求路径显式写 `/api/v1/...`；401 拦截豁免路径同步改为 `/api/v1/auth/session`。
- 测试（conftest + 各 test 文件）路径同步迁移到 `/api/v1/*`。

## 备选

- 无版本前缀（维持现状）：省适配成本，但破坏性变更无法渐进发布。
- Header 版本协商：对当前单体规模过重。

## 后果

- 正向：未来破坏性变更可新增 `/api/v2` 并行演进；前端与测试统一契约，错误解析改为 `error.message`。
- 反向：所有现有客户端路径需一次性迁移；多版本并存时维护成本上升（当前无并存计划）。
- 说明：健康检查未纳入 `/api/v1`，因其不属于业务契约。
