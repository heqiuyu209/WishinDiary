# 研究与提醒迭代

项目主线：以可复现评估驱动周期预测研究。每个功能拆成独立提交，先通过对应测试，再推进下一步。

## 顺序与验收

1. **预测与评估基础**：修复最新窗口、时间索引和评估元数据。可区分历史序列 `[24,25,26,42]` 的下一周期窗口必须为 `[42,26,25]`；时间验证不得使用晚于测试边界的样本；纯合成训练报告不得计为真实样本。
2. **研究管理端**：管理员权限由部署端明确授予；提供汇总数据质量、周期分布、历史记录充分度、实验指标和简单基线对比。普通用户不得访问；管理端不展示用户邮箱、日记或同房记录；把模型选择、数据质量、区间校准作为独立研究方向。
3. **邮箱与提醒**：先支持登录后绑定并验证邮箱，再补注册入口。提醒需主动启用；默认在预计开始前 2 天通知，可选 1/2/3 天；可随时停用或解绑。使用账户时区的当天边界；已开始或已过期的预测不补发；同一周期防止重复提醒；预测变动可取消未发送任务。邮件使用通用标题，健康日期只在登录后查看。
4. **研究深化**：评估完整线上算法（RF + 个人历史收缩 + 取整/裁剪），分别报告新用户泛化和既有用户前瞻预测；保留数据来源与实验版本；默认合成演示，真实数据训练需要独立同意与授权。

## 交付规则

- 保持现有 FastAPI/MySQL/Vue 分层结构，数据库变更通过 Alembic。
- 每个提交写明具体行为变化；为时间窗口、权限、验证过期、防重复发送等业务边界编写回归测试。
- SMTP 默认关闭。开发测试使用模拟传输；实际发送需部署者配置邮件服务。
- 管理端评估文件来自服务器生成的报告，页面不允许任意文件路径、SQL 或在线训练命令。
- 验证通过后推送功能分支并提供 PR；生产启用和数据迁移单独记录部署步骤。
